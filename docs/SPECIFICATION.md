# SPECIFICATION — 사용자 요구사항 전체 명세

> 이 문서는 사용자가 제시한 모든 요구사항의 단일 원본(single source of truth)이다.
> 프레임워크의 어떤 문서·에이전트·게이트도 이 명세와 충돌하면 **이 명세가 이긴다.**
> 마지막 정리: 2026-08-17 (v7 원인 분석 직후)

---

## 0. 절대 Rule — 모든 실행이 수렴해야 하는 6가지

실행이 이 6개에서 발산하면 그 실행은 실패다. 창의성·컨셉·채점 점수는 이 Rule의 하위다.

| # | Rule | 내용 |
|---|------|------|
| R1 | **기획대로 간다** | xlsx 기획안이 **사양서**다. 장면 구성·순서·카피·수치·테이블·배너 조건까지 페이지에 실재해야 한다. 재량은 **조형(레이아웃·타이포·색·리듬)에 국한**되고, 내용(카피·순서·구성·수치)은 기획서 소유다 |
| R2 | **주어진 asset을 쓴다** | 사용자 제공 asset이 1순위(P3). 생성은 부족할 때만(P4). T2(증거성)는 생성 즉시 위조 |
| R3 | **초반에 정한 디자인 시스템대로 간다** | 1단계에서 HITL 승인된 font/color/surface 체계를 이후 단계가 임의 변경 금지 |
| R4 | **추가 지침을 지킨다** | Phase 0 ③에서 확정된 지침은 전 단계의 제약조건 |
| R5 | **템플릿 최대 활용, 안 되면 사유 있는 커스텀** | layout-catalog 템플릿 우선(P2). 커스텀은 "왜 템플릿이 안 되는지" 사유를 플랜에 기록해야만 허용 |
| R6 | **폰트는 주어진 가이드라인대로** | §6 폰트 taxonomy와 config/fonts.json roles에 따라 선택하고, 선택 근거를 플랜에 기록 |

> **디자이너 벤치마크의 교훈**: 같은 기획안으로 디자이너 v3는 기획 카피 원문 52%를 그대로 쓰고도
> 1라운드 83점을 통과했다. **기획 준수와 P1(AI 티 안 나기)은 충돌하지 않는다.**
> "AI 티 안 나기"의 정의는 "독창적 컨셉"이 아니라 **"디자이너 완성본과 구분 불가"**다.

## 1. 북극성 — 4대 원칙

| # | 원칙 | 의미 |
|---|------|------|
| P1 | **AI가 만든 티가 나지 않는다** | 최종 페이지는 디자이너 완성본과 구분 불가. 비평자의 제1 기준 |
| P2 | **정해진 템플릿을 최대한 활용한다** | 커스텀 레이아웃은 템플릿이 정말 안 맞을 때의 예외 |
| P3 | **주어진 asset을 최대한 활용한다** | 사용자가 준 asset이 1순위. 생성은 부족할 때만 |
| P4 | **Image Generation을 이용한다 (Higgsfield)** | 부족한 부품만 생성. P1·컴플라이언스 게이트 통과 조건. Gemini/FLUX는 fallback |

우선순위: **P3 → P4. 주어진 것 먼저, 생성은 그다음.**

## 2. 전체 파이프라인 구조

```
[Skill 실행]
  ↓
Phase 0 — Input 수집·검증 (게이트 통과까지 반복)
  ↓
1단계 Design System → 2단계 Layout 설계 → 3단계 부품 준비 → 4단계 조립
```

### Phase 0 — Input (2레이어 검증)

**Layer 0 — config 접근성** (`pipeline/gate_config.py`): 사람 관할 config 5종이 실제 접근 가능한가
**Layer 1 — 입력물** (`parse_brief.py` + `gate_assets.py`): 사용자가 준 입력 3종

1. **기획서(xlsx)** — 파싱해서 장면·카피·사이드테이블·배너·aux를 읽어낼 수 있어야 Validated
2. **필수 사용 asset** — 경로 실재 + 용도 선언(배경용/참조용). 섞이면 반려, 추측 배치 금지
3. **추가 지침** — 모호하면 되물어 확정. 이후 전 단계의 제약조건

세 게이트 모두 통과해야 1단계 시작.

### 1단계 — Design System 확정

- 개별 페이지가 아니라 **기획 전체를 조망**한 뒤 font/color/surface 체계 수립
- surface = solid/texture/gradient/photo 4어휘의 **비율 선언**. 블록별 즉흥 결정 금지, 단색 >60% 금지
- 산출 범위는 **조형 토큰뿐이다.** 카피 재작성·장면 재편성은 이 단계의 권한이 아니다
- **[HITL] 사람이 approve 하기 전에는 2단계 진입 금지**

### 2단계 — 페이지(장면) 단위 Layout 설계

- **2-1.** 각 기획 페이지별 layout-catalog **템플릿 선택** (P2/R5) — 커스텀은 사유 기록 필수
- **2-2.** 컴포넌트 슬롯에 asset 배치: 주어진 asset부터 소진(P3) → 비는 슬롯만 AI 생성 목록 확정(P4) = 3단계 작업지시서. font/color 배정도 1단계 체계 안에서 여기서
- **2-3.** 플랜 Validate: Rule set(craft-axioms + rules + compliance) 대조 — 용도 준수 / 커스텀 사유 / 생성 목록에 T2 부재 / **기획안 내용 전량 귀속**

### 3단계 — 부품 준비

```
생성 목록 → Higgsfield 생성 → [Validator] 불합격 시 재생성 루프(상한 3회) → 합격 → [HITL] 사람 최종 확인
```

### 4단계 — 조립

- **1~3단계 전략 그대로 조립. 여기서 새로 창작하지 않는다.** 카피·구성 변경이 필요해지면 2단계(플랜)로 회귀해 플랜을 고치고 재승인 후 조립한다
- 빌더 ↔ reviewer(GAN 구도) + red-team 병렬, 기준 **80점 + 실격 0건**, 라운드 상한 4
- **룰을 약화시켜 통과시키는 것 금지**

### 관통 원칙 5

1. Validate 없이는 다음 단계 없다
2. HITL은 **1단계(디자인 시스템 approve)와 3단계(부품 승인)**에 명시적으로 존재
3. **전략은 앞에서, 실행은 뒤에서.** 4단계 즉흥 결정 = 2단계의 실패
4. asset은 용도·계층(배경/참조 × T0/T1/T2)으로 분류된 채로만 흐른다
5. Validator는 하나의 판정 스택, 단계별 적용 룰만 교체 (compliance > craft > 결정론 체커 > reviewer)

## 4. Asset 3계층 + 용도

| 계층 | 정의 | 취급 |
|---|---|---|
| T0 | 절차 생성 (텍스처 등) | `gen_textures.py`, API 불필요 |
| T1 | AI 생성 가능 | Higgsfield, compliance 게이트 통과 조건 |
| T2 | 증거성 (실사·후기·판매실적·특허·인물) | **사람만 제공 가능. 생성 = 위조.** 미도착 시 [기획자 입력] designed placeholder로 자리만 |

용도: **배경용**(직접 깔림) / **참조용**(스타일 참조만, 직접 배치 금지) — 선언 없이 유입되면 반려.

## 5. 입력 독립성 원칙 (런의 경계)

목표는 **다양한 입력에 잘 동작하는 파이프라인**이다. 구스밀은 테스트 입력일 뿐이다.

| 계층 | 내용 | 위치 |
|---|---|---|
| 시스템 상태 | 규칙·공리·체커·템플릿·레시피 (모든 입력 공통) | docs/, pipeline/, .claude/ |
| 실행 상태 | 이 입력의 플랜·판정·에셋·사실 | data/briefs/, data/assets/ |

1. 새 입력의 실행은 **시스템 상태만** 참조한다 — 타 제품 plan·판정 이력 참조 금지
2. 같은 제품 재실행이 승계 가능한 것: compliance 판정·확정 수치·T2. 불가: **디자인 시스템(매 실행 재도출)**
3. **제품의 사실은 plan.json이 소유한다** (fact_checks). 체커·스킬에 하드코딩 금지
4. 체커로 이관하는 것은 일반화 가능한 규칙만
5. 문서의 제품 사례 인용은 정당하나 **사례는 규칙이 아니다**

## 6. 폰트 가이드라인 (사용자 제공 taxonomy — AS-IS 적용)

- **세리프 = 디폴트.** 특별한 무드 요구가 없으면 세리프
- **산세리프 = 무드 조건부**: 고급 / 프리미엄 / 여성적 / 이국적 무드일 때
- 하위분류: **손글씨**(감성·수제) / **장체**(응축·임팩트) / **볼드 캐릭터**(강한 선언) / **귀여움**
- 폰트는 **Figma 클라우드에 있어야 사용 가능**. 로컬 다운로드 금지, `listAvailableFontsAsync`로 검증
- 커스텀 폰트는 **개인 계정 업로드**(Pro 가능)로 편입 — Pretendard 9w, Gmarket Sans TTF 3w 업로드·검증 완료
- 한국어 기본: Noto Sans KR. 허용 목록·role 매핑은 `config/fonts.json`이 원본
- **플랜은 각 폰트 선택이 어떤 role 규칙에서 나왔는지 근거를 기록해야 한다** (R6)

## 9. 검수 체계

- 4-layer 판정 스택: **compliance(법) > craft(실격 공리 F1~F10) > 결정론 체커(qa_check.py) > reviewer(미감)**
- reviewer ∥ red-team **독립 병렬** (서로 출력 참조 금지), 빌더 자기설명 읽기 금지 (입력 격리)
- 채점은 이진 체크 산술 — 홀리스틱 인상 점수 금지
- 통과: 80점 + 실격 0건. 라운드 상한 4. **어떤 경우에도 룰을 약화해 통과시키지 않는다**
- reviewer의 벤치마크는 검수 통과가 아니라 **디자이너 완성본**
- **검수는 기획 대비 검수를 포함한다**: 기획안 내용이 페이지에 실재하는가가 미감보다 먼저다 (R1)
