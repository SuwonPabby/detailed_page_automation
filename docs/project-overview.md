# project-overview — 무엇을, 어디까지 자동화하는가

## 목표

한국 이커머스 **상세페이지**(폭 860px, 길이 1~5만 px의 롱폼 페이지) 제작을 자동화합니다.

## 1. 현재(As-Is) 워크플로우

```
기획안 xlsx 작성  →  asset 준비  →  디자이너 상세페이지 제작  →  선우 QA  →  수정  →  선우 QA  →  ...
                    (자동화 완료)        (여기가 대상)              (Iteration)
```

### 입력물

| 입력 | 설명 | 상태 |
|---|---|---|
| 기획안 xlsx | 양식이 정해져 있음 | 별도 작업으로 생성됨 |
| Asset | 디자인에 필요한 소재를 직접 추출 | **이미 자동화 완료 — 이 프로젝트 범위 밖** |
| 템플릿 | 참고용 | 존재 |

### 디자이너가 참고하는 정보

- **(Main 정보)** 기획안 xlsx 중 "기획안" sheet — 페이지에 들어갈 실제 내용
- **(부가 정보)** 같은 xlsx의 다른 sheet — 전체 디자인 방향성과 인사이트를 얻기 위해 볼 수도 있음
- 템플릿
- 미리 확보된 asset

### 디자이너의 실제 작업 순서

1. 아주 기본적인 **디자인 시스템**을 먼저 뽑는다 — 폰트 / 색상 / 주요 키워드
2. 기획안 내용을 디자인 시스템 + asset으로 **어떻게 표현할지** 고민
3. 레퍼런스에서 **레이아웃 위주로** 참고 — 핀터레스트, 템플릿

### 디자이너의 머릿속 (⭐ 에이전트가 모방해야 할 사고 순서)

> 1. 기획안을 **장면(scene) 단위**로 읽는다
> 2. 그 장면을 표현할 **적절한 레이아웃**을 찾는다
> 3. 레이아웃이 정해지면 **디자인 시스템은 잠시 제쳐두고**, 어떤 정보가 어떤 위치에 올지를 생각한다
> 4. 정보 배치 스케치가 나오면, **그제서야** 디자인 시스템에 맞는 컴포넌트로 치환한다

**핵심: 레이아웃이 먼저, 스타일링은 나중.** 이 순서를 뒤집으면 디자이너의 결과물이 나오지 않습니다.

### QA 단계

- 나온 안에 **Figma 댓글**로 피드백을 단다
- 디자이너가 반영 → 다시 QA → Iteration

## 2. 자동화 범위

### Level 1 — 디자이너 워크플로우 자동화

| | 내용 |
|---|---|
| **입력** | 기획안 엑셀 · 디자인 시스템 · 필요한 asset 리스트 · 레퍼런스 |
| **출력** | **상세페이지 제작이 완료된 Figma** |

### Level 2 — AI 선행 QA

```
현재:        디자이너 → 선우 QA → 디자이너 → 선우 QA
Level 1 후:  AI      → 선우 QA → AI      → 선우 QA
Level 2 후:  AI → AI 선행 QA → AI → AI 선행 QA → (AI 승인) → 선우 QA
```

Level 2의 판단 기준이 바로 [design-principles.md](./design-principles.md)에 추출해둔 규칙들입니다.

## 3. Level 1 사용자 인터페이스 (구상)

**골든 프롬프트를 입력해 실행하면 Output이 Figma에 나타난다.**

필요 요소:

- **Golden Prompt** — 실행을 위한 프롬프트
- **자료 폴더** 하나에 아래를 정리:
  - 기획안 엑셀
  - 디자인 시스템
  - 필요한 asset 리스트
  - 레퍼런스
  - **Output이 나올 Figma 링크**
