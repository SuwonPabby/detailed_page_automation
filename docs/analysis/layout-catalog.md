# layout-catalog — 레이아웃 패턴 카탈로그

> 상태: **초안 (M1 파일럿 기준, 16패턴)** — M2~M4에서 예시 축적 + anti-pattern 절 추가 예정.

블록의 **구성 골격** 카탈로그. 장면(scene)을 정한 뒤(디자이너 사고 2단계) 여기서 후보 패턴을 고른다.

**사용 규약:**
- 예시 노드 ID를 `get_screenshot(fileKey="jjgud5OkeXKA4weyP3FEND", nodeId=...)` 으로 **그 자리에서 띄워 확인**한다. 이미지는 저장소에 없다 — Figma가 원본이다.
- **인접 블록에 같은 패턴을 쓰지 않는다** (design-principles C항 — "비슷한 레이아웃 반복" 실패 근거: 일진와이어·토마토).
- 하나의 블록은 보통 **패턴 2~3개의 결합**이다 (예: `numbered-point + compare-2up + evidence-callout`).

## 파일럿에서 관찰된 결합 규칙

1. **usp 블록의 표준 골격**: (넘버 헤더) → (헤드라인+본문) → (시각 근거 1~2개) → (콜아웃 마무리). 시각 근거 자리에 compare-2up / evidence-chart / process-seq / radial-diagram 중 하나가 들어가며, **usp 연작 안에서 근거 패턴을 매번 바꾼다** — 글로우샷 POINT 1~5는 compare→chart→process→radial+chart→radial로 전부 다르다. 이것이 C항(다양성)을 지키는 실제 메커니즘.
2. **차트는 반드시 흰 카드에 격리**된다. 배경 위에 직접 그리지 않는다.
3. **근거에는 출처 각주**(작은 글씨, 괄호 인용)가 붙는다 — 식약처/논문/시험 기준.
4. **콜아웃은 블록당 1회**. 남발된 사례 없음.
5. 풀블리드 컬러 블록 위 콘텐츠는 **흰 라운드 카드**에 담는다 (글로우샷 `1:394`, 파일변환 `1:84605`).

## Anti-patterns (M4에서 Bad 페이지 실측으로 확장 예정)

- 인접 블록 동일 패턴 반복 — 일진와이어("33, 13이 비슷함")·토마토("섹션 8과 9 반복") 지적 사항
- 구매후기 전문 나열 — Bad `Section 4` 지적: "더 작게 효율적으로"
- 이미지 위 텍스트 대비 미확보 — 간편블럭국 지적: "이미지와 수상기록이 겹쳐서 눈에 들어오지 않음"
