# scene-taxonomy — 장면(블록) 유형 분류 체계

> 상태: **초안 (M1 파일럿 기준)** — 글로우샷 14블록 + 파일변환 6블록으로 검증.
> M2~M3에서 나머지 7개 Good 제품을 라벨링하며 갱신되고, M3에서 전이 패턴 통계가 추가된다.

상세페이지는 **장면(scene)의 세로 시퀀스**다. 기획안을 장면 단위로 분해할 때(디자이너 사고 1단계)
아래 통제 어휘로 각 장면의 역할을 판정한다. 모든 라벨은 `data/blocks.json`에 노드 ID와 함께 기록된다.

## 장면 유형 (통제 어휘)

| scene_type | 역할 | 파일럿 실측 예시 (블록 노드 ID) |
|---|---|---|
| `hook` | 첫 블록. **제품이 아니라 소비자의 문제/질문으로 시작** | 글로우샷 `1:4`, 파일변환 `1:84755` |
| `problem` | 독립된 문제 심화 블록 (hook과 분리될 때) | *(파일럿에는 hook에 병합됨)* |
| `solution-frame` | 해결의 프레임 제시 — 제품 등장 전 "올바른 방법은 이것" | 글로우샷 `1:25` |
| `product-reveal` | 제품 첫 등장. 풀블리드 히어로 | 글로우샷 `1:46` |
| `usp` | 핵심 셀링포인트. **넘버링되어 3~5회 반복** (POINT n / 특징 n) | 글로우샷 `1:58` `1:97` `1:211` `1:251` `1:320`, 파일변환 `1:84713` `1:84662` `1:84621` |
| `comparison` | 비교가 블록의 주목적일 때 (자사 vs 타사, before/after) | *(파일럿에선 usp 내부 요소로만 등장)* |
| `ingredient-spec` | 성분/원료/스펙 표 | *(파일럿 미등장 — 식품군 M2에서 예상)* |
| `transition` | 서사 전환용 짧은 스트립 | 글로우샷 `1:90` |
| `trust-cert` | 인증·수상·시험 (GMP, 건기식 배지 등) | 글로우샷 `1:356` |
| `benefit-recap` | 베네핏 감성 재확인 — 컨셉 키워드 회수 | 글로우샷 `1:371` |
| `target-audience` | "이런 분께 추천" 체크리스트 | 글로우샷 `1:394` |
| `usage-guide` | 섭취법/사용법/이용 방법 | 글로우샷 `1:427`, 파일변환 `1:84605` |
| `review` | 구매후기 (압축 필수 — design-principles F항) | *(파일럿 미등장)* |
| `cta-offer` | 구성/가격/이벤트 | 파일변환 `1:84621` 하반부(usp와 결합) |
| `faq` | 자주 묻는 질문 | 글로우샷 `1:487`, 파일변환 `1:84546` |
| `notice` | 정보고시/주의사항 | *(파일럿 미등장)* |
| `brand-story` | 브랜드 서사 | *(파일럿 미등장)* |

## 파일럿에서 관찰된 서사 시퀀스

```
글로우샷 (14블록, 이너뷰티 건기식):
  hook → solution-frame → product-reveal → usp×2 → transition → usp×3
       → trust-cert → benefit-recap → target-audience → usage-guide → faq

파일변환 (6블록, B2B 서비스):
  hook → usp×3(마지막에 cta-offer 결합) → usage-guide → faq
```

### 파일럿에서 확인된 서사 원칙 (초안 — M3 통계로 확정 예정)

1. **문제로 열고, FAQ로 닫는다.** 두 제품 모두 hook은 소비자 문제 질문이고, 마지막 블록은 FAQ다. 제품 자랑으로 시작하지 않는다.
2. **usp는 넘버링된 연작이다.** POINT 1~5 / 특징 1~3처럼 명시적 번호로 반복되며, 페이지 본문의 중심 덩어리를 이룬다.
3. **usp 안에 근거가 내장된다.** 임상 차트·비교 이미지·인용 출처가 usp 블록 내부 요소로 들어간다. 독립된 "근거 블록"은 없었다.
4. **긴 페이지는 전환 스트립으로 호흡을 끊는다.** 글로우샷은 usp 다섯 개를 2+3으로 나누고 그 사이에 513px 전환 블록을 넣었다(수분→지방 서사 전환).
5. **후반부는 신뢰→감성→행동 순.** trust-cert → benefit-recap → target-audience → usage-guide → faq. 스펙 다음에 감정을 회수하고, 실행 정보로 내려간다.

## 라벨링 규칙

- 한 블록이 두 역할을 겸하면 **주된 역할**을 `scene_type`으로, 부역할은 `notes`에 기록 (예: 파일변환 `1:84621` = usp + cta-offer 결합).
- 판정 근거는 시각(스크린샷)과 텍스트 내용 모두 사용. 텍스트에 "FAQ", "이용 방법" 등 명시 단어가 있으면 우선.
- 새 유형이 필요하면 이 표에 추가하고 커밋 메시지에 사유를 남긴다. 기존 라벨 재검토 필요 여부도 함께 판단.
